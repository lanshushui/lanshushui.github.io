# Link 一个 DLL (SO) 文件

1. 利用 clion 创建一个 aplication 工程，cmke 文件如下

CMake 中的 link_directories 与 target_link_directories：用途与区别

cmake_minimum_required(VERSION 3.28)
project(executabledemo)

set(CMAKE_CXX_STANDARD 17)
add_executable(executabledemo main.cpp )
#给executabledemo文件 添加link的目录
target_link_directories(executabledemo PRIVATE ${CMAKE_SOURCE_DIR})
#实际link librarydemo
target_link_libraries(executabledemo  librarydemo)

2. 将 library.h，liblibrarydemo.dll 文件复制到源目录下，修改 main.cpp 内容

#include "./library.h"
int main() {
    hello();
    return 0;
}

3. 执行右上角运行，第一次会运行失败 Error 0xc0000135，因为执行 link 成功，但运行时还是找不到动态库。所以我们要把 liblibrarydemo.dll 文件再次复制到 build 目录下，即 executabledemo.exe 同级目录，再次运行即可正常运行

# 应用场景

A.so link B.so 的场景下:

要点 1：由 B 工程写头文件，和实现。A 工程通过 B 工程提供的头文件向 B 通信。

要点 2：如果 B 工程需要向 A 工程通信，可以通过头文件设置 std::function 回调函数的方式进行。不能 B 定义一个类的头文件，A 实现类的方法，通过要点 1 传这个类的实例给 B，让 B 调用类方法实现 B 向 A 工程通信，因为类的实现在 A 工程的话，B 调用类的方法是找不到类函数实现而无法编译通过。

要点 3：由于 struct 的属性是按偏移量来读取的，所以 A 工程的回调函数可以返回 struct 结构数据，只要两个工程都定义了一样的数据结构。
